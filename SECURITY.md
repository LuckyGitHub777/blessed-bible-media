# Security Policy

## Scope

Public media distribution and metadata surface. Publishing controls and provider credentials belong in a separate private repository.

Reports about published personal data, image metadata, license mistakes or asset integrity are in scope. Never include private publishing tokens or publication receipts in reports.

## Responsible reporting

Do not publish credentials, tokens, personal information, vulnerability reproduction details, or sensitive content in public GitHub issues, pull requests, discussions, or workflow logs.

If the repository's Security tab offers GitHub's private **Report a vulnerability** flow, use it. Otherwise open a public issue requesting a private reporting route **without disclosing the details**. A public issue is not confidential.

Provide the affected version or file, observed impact, and sanitized reproduction steps through the private route. Do not test third-party systems without permission. No response-time guarantee or security certification is implied by this policy. Licensing, attribution, release assets and history are unchanged.
